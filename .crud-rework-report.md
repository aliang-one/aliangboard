# CRUD Factory Rework — All-Real-Data Architecture

## New `makeCrud` (pure-remote, Vue Query cache)

Built per spec §1. Key design:
- **No `remoteMode`/`store-ref`/`mock`**: factory is pure-remote.
- **`fromCache(name, ns)`**: reads current item from Vue Query cache (`queryClient.getQueryData(['cluster', cid, plural])`). This replaces the old `idxOf` on store list refs.
- **`add(item)`**: `remoteCreate(yamlOf(item), label)` → `sideEffects.onAdd` → `invalidateResource(plural)`.
- **`update(name, ns, updates)`**: `patchFn` resources (HPA) → `remotePatch(itemApi, patchFn(...))`; others → `fromCache` merge → `remoteUpdate(yamlOf(merged))`. Cache miss → just `invalidateResource` (no throw).
- **`delete(name, ns)`**: `remoteDeletePath(itemApi, label)` → `sideEffects.onDelete` → `invalidateResource`.
- **`remoteDeletePath`**: new factory-only primitive — pure `api.k8s DELETE`, no store-ref optimistic delete (Vue Query invalidate syncs). Kept old `remoteDelete(path, list, matchFn, label)` for bespoke hand-written resources.

## RESOURCE_SPECS (17 entries, no `ref` field)

configmaps, secrets, pvcs, services, networkpolicies, hpas, resourcequotas, limitranges, serviceaccounts, rolebindings, poddisruptionbudgets, ingresses, ingressclasses, runtimeclasses, priorityclasses, clusterrolebindings.

Hooks preserved:
- **`beforeSave`** (secrets): `encodeSecretData` on data before YAML gen.
- **`patchFn: hpaPatchFn`** (hpas): targeted patch body (minReplicas/maxReplicas/metrics only — no behavior prune).
- **`genExtra: true`** (pdbs, priorityclasses): uses `generateExtraYAML` instead of `generateYAML`.
- **`sideEffects`** (services): onAdd/onDelete → namespace.services count (still mutates `namespaceList.value` store ref — namespace list is a store ref in both old and new architecture; this is safe).

`hpaPatchFn` exported at module level for direct unit testing.

## 17 hand-written CRUD sets deleted

All `add`/`update`/`delete` functions replaced by factory products for: services, ingresses, configmaps, secrets, pvcs, networkpolicies, hpas, resourcequotas, limitranges, serviceaccounts, rolebindings, poddisruptionbudgets, ingressclasses, runtimeclasses, priorityclasses, clusterrolebindings.

**Kept hand-written** (bespoke, not in this rework): workload, namespace, PV, SC, roles, pod, crd, endpoints, nodes (cordon/uncordon/drain).

**Kept `updateIngressRules`** hand-written (special PATCH for ingress routing rules).

Getters (`getXxxByName`) kept hand-written (they read store refs, not factory products).

## sideEffects in Query model decision

Service's `sideEffects` (namespace.services count) was preserved as-is — it mutates `namespaceList.value` (a Pinia store ref). In the all-real-data model, namespaces are hydrated into the store ref via `hydrateCriticalResources` (the 2-request critical path). The service sideEffect is a cosmetic counter on namespace cards; it's safe to keep mutating the store ref since namespace cards read from it. Invalidating the full namespace query is unnecessary for a counter increment.

## Test approach (`cluster.crud-factory.test.js`, 17 tests)

- Mock `@/api/client` (stub `api.applyYaml` + `api.k8s`) + `@/queryClient` (spy `getQueryData`/`invalidateQueries`).
- Per-resource assertions: add → `applyYaml` called with correct YAML kind; update → cache lookup → `applyYaml`/`k8s PATCH` with correct path/body; delete → `k8s DELETE` with correct path.
- `hpaPatchFn` pure function tests (2): structure correctness + update override semantics.
- Secret `beforeSave` regression test: verifies `stringData` path in YAML (proves beforeSave → encodeSecretData → generateYAML chain).
- HPA `patchFn` test: verifies targeted patch body (no behavior/scaleTargetRef prune).
- Cache-miss boundary test: update with empty cache → no `applyYaml`, just `invalidateQueries`.
- Store wiring test: all 17 resources expose add/update/delete.
- Cluster-level path tests (ingressclass, priorityclass, clusterrolebinding): no-ns path correctness.

## Concerns

1. **`remoteCreate` refreshFn dropped**: old `remoteCreate(yaml, label, refreshFn)` passed a refetch callback; factory calls `remoteCreate(yaml, label)` without it (no store ref to refresh). Vue Query `invalidateResource` handles list refresh. This is correct for the new model.
2. **Cluster-level update signatures**: old `updateIngressClass(name, updates)` / `updateRuntimeClass(name, updates)` / `updatePriorityClass(name, updates)` / `updateClusterRoleBinding(name, updates)` had `(name, updates)` signature. Factory produces `update(name, ns, updates)`. No `.vue` callers of these update functions exist (verified via grep), so signature change is safe.
3. **`decodeBase64` in test env**: happy-dom's `atob` may not handle UTF-8; the secret update test asserts `stringData:` presence (structural) rather than decoded value. This is a test-env limitation, not a production issue.
