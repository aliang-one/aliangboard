# Wave 4 OIDC(SSO 登录)实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Checkbox steps.

**Goal:** 落地 Wave 4 spec——零依赖 OIDC(授权码+PKCE+兑换码)、JIT 建户+组同步(claims 接管供给)、登录页 SSO 钮 + Settings 配置卡。

**Architecture:** `server/jwt-verify.mjs`(JWK→KeyObject+JWT 全验,纯函数)+ `server/oidc.mjs`(discovery/JWKS 缓存+state/兑换码 Map+流编排,deps 注入 fetchImpl);三 none-class 端点(login/callback/exchange)挂 auth.mjs 旁;JIT+组同步走事务(全量对齐);OIDC 用户 passwordHash=NULL(本地登录天然不可用)。开关默认关=存量零感知。

**Tech Stack:** node:crypto(RSA/EC/HMAC 验签)、node:test、Vue3+vitest。零新依赖。

**Spec:** `docs/superpowers/specs/2026-09-07-usercenter-wave4-oidc-design.md`(D1-D6 + §1-§8)

### Task 1: server/jwt-verify.mjs(纯函数:base64url + JWK→KeyObject + JWT 全验)

**Files:** Create `server/jwt-verify.mjs`;Test Create `server/jwt-verify.test.mjs`
**Interfaces (Produces):**
- `base64urlDecode(s) -> Buffer`
- `decodeJwtSegments(token) -> { header, claims, signature:Buffer }`(格式错 throw 'malformed')
- `jwkToKeyObject(jwk) -> KeyObject|Buffer`(RSA{n,e}->createPublicKey({key:'rsa',n,e}) via JWK→DER 或 keyObject 构造;EC{crv,x,y}->createPublicKey({key:'ec',...});oct{k}->Buffer(HS256 secret);不认识的 kty throw 'unsupported-key')
- `verifyJwtSignature(header, signature, claims, key) -> boolean`(RS256/ES256 用 crypto.verify('RSA-SHA256'|依 crv, payload, key, sig);HS256 用 createHmac+timingSafeEqual;alg 白名单 ['RS256','ES256','HS256'],header.alg 不在 → throw 'unsupported-alg')
- `verifyIdToken(token, { jwks, issuer, audience, nonce, now=Date.now() }) -> { claims }`——找 kid 匹配 jwks.keys[](无 kid/不匹配 throw 'unknown-kid')→ 验签(false throw 'bad-signature')→ iss!==issuer throw 'issuer';aud 不含 audience throw 'audience';exp<now throw 'expired';nonce!==给值 throw 'nonce';iat>now+300000 throw 'iat-future'。返回 claims。

- [ ] Step 1 失败测试——**真签名非 mock**:node:crypto generateKeyPairSync('rsa')/('ec', prime256v1) 自签 JWT,每个通过分支+每个 throw 分支一例;HS256 用 randomBytes secret;JWK 从 export({format:'jwk'}) 直接取(真实形状);kid 匹配/不匹配;exp 过去/未来;iat 未来;aud 数组形态(Audience Arrays:['a','b'] 含目标)。
- Step 2-5 → Commit `feat(server): zero-dependency JWT verification (JWK→KeyObject, RS256/ES256/HS256, full claim checks)`

### Task 2: server/oidc.mjs(provider 模块:discovery/JWKS 缓存 + 流原语)

**Files:** Create `server/oidc.mjs`;Test Create `server/oidc.test.mjs`
**Interfaces:**
- Consumes: Task 1 verifyIdToken。
- Produces: `createOidcProvider({ getSetting, fetchImpl })` →
  - `isEnabled() -> boolean`(oidc.enabled==='1' 且 issuer/clientId 齐)
  - `getPublicConfig() -> { enabled, issuer, clientId, scopes, groupsClaim, usernameClaim, hasSecret }`(clientSecret 永不出)
  - `getFullConfig() -> |null`(内部,含 clientSecret)
  - `discovery(issuer) -> Promise<doc>`(GET `<issuer>/.well-known/openid-configuration`,校验含 authorization_endpoint/token_endpoint/jwks_uri/issuer;缓存 Map<issuer,{doc,at}>,TTL 12h;`_clearOidcCacheForTest()` 导出)
  - `jwksFor(issuer) -> Promise<jwks>`(走 doc.jwks_uri;缓存 Map<jwksUri,{keys:Map<kid,key>,at}> TTL 12h)
  - `buildAuthUrl({ doc, clientId, redirectUri, state, nonce, codeChallenge, scopes }) -> string`(拼 authorization_endpoint + response_type=code + scope)
  - `exchangeCode({ doc, clientId, clientSecret, redirectUri, code, codeVerifier }) -> Promise<{ idToken }>`(POST token_endpoint,form-encoded,client_id+client_secret+grant_type=authorization_code+code+redirect_uri+code_verifier;取 json.id_token,无 → throw 'token')
  - `verifyCallbackIdToken(idToken, issuer, clientId, nonce, { refreshJwks } )`——jwks 缓存验,unknown-kid 时强刷一次再验(then fail)
- fetchImpl 注入(默认 globalThis fetch);fetchImpl(url, init) 返回 { ok, status, json() } 桩形状即可。

- [ ] Step 1 失败测试:discovery 文档校验/缓存命中(计数)/坏文档 throw;jwks 缓存+kid 索引+强刷一次;buildAuthUrl 含全部参数 URL-encoded;exchangeCode form body 形状(桩捕获 body 断言 urlencoded 串)+ id_token 缺失 throw;isEnabled 组合矩阵;getPublicConfig 无 secret。
- Step 2-5 → Commit `feat(server): OIDC provider module — discovery/JWKS caching, auth-url, code exchange, id-token verify with kid refresh`
